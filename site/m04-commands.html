A slash command is the shortest path from intent to action in Claude Code. Built-in commands run fixed logic in the client: they show what fills the context, what you have spent, and how the session is set up. Your own commands are prompts kept in files: reviewed, versioned and called by name, from a terminal or from a script.

After this module you can

  • Pick the right built-in command for a context, money or setup question, and say which of them also run headless.
  • List the commands a session actually has, from the slash_commands field of the stream-json init line.
  • Write a project command that takes positional and named arguments, and avoid the 0-based and quoting traps.
  • Inject live data into a command with !`…`, prove the data reached the model, and turn the feature off with disableSkillShellExecution.
  • Pin a command to a cheaper model with frontmatter and confirm the model from modelUsage.
  • Decide whether a repeated task belongs in a command, a hook or a plain script, and give a command a done-test.

What you need

  • Claude Code 2.1 or later, signed in (plan or API key). The labs were run on 2.1.322.
  • Windows PowerShell 5.1 or later, and git on the PATH (lab 3).
  • About $0.05 of API usage for all labs, or a small share of a plan's 5-hour window.

If you skipped the prerequisites

This module leans on the Context module. Every request Claude Code sends carries the whole conversation so far, on top of a fixed prefix: the system prompt, the tool definitions, your CLAUDE.md files and the one-line descriptions of the skills that are available. That prefix is several thousand tokens before you type anything, and most of it is served from the prompt cache on later turns. The context window on current models is 1 million tokens; Claude Code compacts automatically when the conversation nears that limit. /compact replaces the conversation with a summary and keeps going; /clear starts an empty conversation and keeps project memory. Anything a command adds to the prompt, including the output of a shell command it runs, becomes part of the conversation and is re-sent on every later turn until you compact or clear.

A message that starts with / is a command. Only the start of the message counts: the text after the name becomes the command's arguments. Two kinds of command share the / menu. Built-in commands are coded into the client and run fixed logic: /context draws a chart, /model switches the model, and neither calls the model. Bundled skills, such as /doctor, /code-review and /batch, are prompts that ship with Claude Code: invoking one hands Claude a set of instructions and lets it do the work with its tools. Your own commands, covered from the next lesson on, are the same kind of thing as bundled skills.

Read the real list from the session

Documentation describes every command; your session has a subset that depends on platform, plan, login and what is installed. The authoritative list for a run is the first line of stream-json output, the system/init message. Its slash_commands array holds every name the session accepts, built-in and custom, and its skills array the skill names. On a clean project folder with 2.1.322 that list had 53 names; it included context, compact, clear, usage, model, effort, mcp, agents and doctor, and did not include permissions, hooks, memory or plugin. Lab 1 has you read your own.

A command name typed after other text does not run. please /compact now is an ordinary message; for a skill it only counts as permission for Claude to invoke it. Put the command first.

A custom command is a Markdown file whose body is a prompt. When you type its name, Claude Code reads the file, substitutes the arguments, runs any shell injections, and sends the result to the model as your message. The model never sees the file name or the frontmatter; it sees the rendered text.

Two formats, one mechanism

Custom commands have been merged into skills. A file at .claude/commands/deploy.md and a skill at .claude/skills/deploy/SKILL.md both create /deploy and behave the same way. The command file is the older format and still works. The skill format adds a folder for supporting files and the name and paths frontmatter fields; everything else in this module works in both.

A minimal command file has no frontmatter at all. This one is complete:

---
description: Restart note for a host
---
Reply with exactly: RESTART-NOTE for $ARGUMENTS

Run headless as claude -p "/ops:restart web-01", it returned RESTART-NOTE for web-01, and the init line listed ops:restart in slash_commands.

Name clashes

Names collide more often than you expect, because the personal, project, enterprise and bundled namespaces are flat. The rules:

Same name inWhich one runs
A skill and a file in .claude/commands/The skill. Lab 2 confirms it: /clash answered FROM-SKILL.
Enterprise, personal and projectEnterprise over personal, personal over project.
Yours and a bundled skill or built-inYours replaces it, but not its aliases. A project usage skill replaces /usage; /cost still runs the built-in.
A plugin skill and any of the aboveBoth load: the plugin one is always /plugin-name:skill-name.
A root skill and a nested one in apps/web/.claude/skills/Both load: /deploy runs the root one, /apps/web:deploy the nested one.
The personal-over-project rule means a teammate's ~/.claude/skills/deploy silently replaces the reviewed /deploy in your repository, on their machine only. Give team commands a prefix that nobody uses personally, or ship them in a plugin where the namespace is enforced.

Who may invoke it

By default both you and the model can invoke a command: its description sits in the skill listing, and Claude may call it through the Skill tool when it judges it relevant. Two frontmatter fields change that.

FrontmatterYou can invokeClaude can invokeDescription in context
(default)YesYesAlways
disable-model-invocation: trueYesNoNo
user-invocable: falseNoYesAlways

For anything with side effects, such as deploying, committing or posting, set disable-model-invocation: true. It also takes the description out of every session's prefix, which is a small token saving per command.

With a model-invocable command and --max-turns 1, a headless run of claude -p "/ops:restart web-01" ended with subtype error_max_turns and an empty result: Haiku spent its only turn calling the Skill tool on the command that was already loaded. Allow two or three turns, or set disable-model-invocation: true.
Write a command as a skill folder when it needs supporting files or a name different from its folder; otherwise a single file in .claude/commands/ is enough.

Whatever follows the command name is the argument string. Claude Code substitutes it into the body before the model sees anything. There are four placeholder forms.

PlaceholderExpands toWith /echo-args web-01 'disk full'
$ARGUMENTSThe whole argument string as typed.web-01 'disk full'
$ARGUMENTS[N] or $NArgument N, counting from 0.$0 = web-01, $1 = disk full
$2 with no third argumentNothing: the placeholder stays as literal text.$2
$nameA named argument from the arguments frontmatter list, mapped by position. Empty if missing.with arguments: [host, symptom], $host = web-01

The third column is real output. This body

---
description: Echo back the arguments it received
argument-hint: <host> <symptom>
disable-model-invocation: true
---
Reply with exactly this one line and nothing else:
FIRST=$0 | SECOND=$1 | THIRD=$2 | ALL=$ARGUMENTS

returned:

FIRST=web-01 | SECOND=disk full | THIRD=$2 | ALL=web-01 'disk full'

The 0-based trap

Shell scripts number from $1. Claude Code numbers from $0. A body written by habit as "restart $1 on $2" puts the second argument where the first belongs and leaves a literal $2 in the prompt. The model then improvises, usually plausibly, so nothing fails loudly. Named arguments avoid the whole class of error:

---
description: Draft a restart plan for one host
arguments: [host, reason]
argument-hint: <host> <reason>
disable-model-invocation: true
---
Draft a restart plan for $host. Reason given: $reason.

Quoting

Indexed arguments use shell-style quoting: quote a multi-word value to keep it as one argument. In Windows PowerShell 5.1 that collides with how arguments reach native programs. The run claude -p "/echo-args web-01 `"disk full`"" produced SECOND=disk and ALL=web-01 disk: PowerShell split the prompt at the embedded quotes and the word full never arrived. Single quotes inside the double-quoted prompt went through intact, as the table shows.

In PowerShell 5.1, never put double quotes inside a claude -p prompt. Use single quotes to group a multi-word argument.

Other details that matter

  • If the body has no placeholder at all, Claude Code appends ARGUMENTS: <what you typed> to the end, so arguments are never silently lost.
  • An argument that itself contains $1 or $ARGUMENTS is inserted literally and not expanded again.
  • To write a literal $1.00 in a body, escape it: \$1.00.
  • argument-hint only changes the autocomplete hint in the / menu. It validates nothing.
  • ${CLAUDE_SESSION_ID}, ${CLAUDE_EFFORT}, ${CLAUDE_SKILL_DIR} and ${CLAUDE_PROJECT_DIR} are also substituted, which lets a body point at a script by absolute path.
  • At the terminal you can stack up to six skills in one message (/write-tests /fix-issue 123). Through claude -p only the first one loads and the rest of the line becomes its arguments.
Use named arguments for anything with more than one parameter; keep $ARGUMENTS for free text.

A command body can run shell commands before the prompt is sent. The output replaces the placeholder, so the model receives data, not an instruction to go and fetch it. Two forms exist:

---
description: Report the ticket in the newest commit body
disable-model-invocation: true
---
Body of the newest commit:
!`git log -1 --format=%b`

Reply with only the ticket id from that body, or NONE if you see no ticket id.

The inline form !`command` is recognized only at the start of a line or after whitespace; KEY=!`cmd` stays literal. For several lines, open a fenced block with three backticks followed by !; each line in it runs.

When it runs and how

  • Once, at invocation, on your machine. Substitution runs over the file once. Output is not re-scanned, so a command cannot emit another placeholder.
  • Through the session's shell tool. Bash when it is available, otherwise PowerShell. The frontmatter field shell: powershell selects the PowerShell tool; shell: bash on Windows without Git Bash fails the invocation. Commands like git log run the same in both.
  • In the session's current directory, which moves when Claude runs cd. Use ${CLAUDE_PROJECT_DIR} in paths that must not drift.
  • Under the Bash tool's 2-minute timeout. Output beyond the tool's inline ceiling arrives as a file path plus a preview.
  • Under your permission rules, without prompting. A command your rules do not allow aborts the whole invocation with Shell command permission check failed. Read-only commands such as git log pass; anything else needs a rule or the command's allowed-tools.
  • All or nothing. A non-zero exit aborts the invocation and Claude never sees the body. Exit 1 from search and compare commands is tolerated; append || true under bash to a check that exits 1 on findings.

Prove the output reached the model

Do not test injection with data the model can already see. A headless session's prompt already carries a short git status snapshot with recent commit subjects: asked for the newest commit subject with injection switched off, Haiku still answered correctly and said it had read it "from the git status snapshot at the start of the conversation". Put a random marker where the snapshot does not reach, such as the commit body, and ask for it back. Lab 3 does that: with injection on the run returned the random ticket-20006; with injection off it returned NONE.

What it costs

Injected output is ordinary prompt text. It is billed as input or cache write on the turn you invoke the command, and the rendered command stays in the conversation afterwards, so it is re-sent as cache read on every later turn until you compact or clear. A git log -1 is a few dozen tokens. A git diff of a large branch or a recursive file listing can be tens of thousands, paid for the rest of the session. Invoking the command again with different output appends a second full copy; an identical render adds only a short note.

Subscription planAPI key
A 20,000-token injectionDraws down the 5-hour window on that turn, and a smaller amount on every later turn as cache read.Billed once as input or cache write, then at the cache read rate per turn.

Turning it off

The setting disableSkillShellExecution: true replaces every injection in user, project, plugin and added-directory commands with [shell command execution disabled by policy]. Bundled skills and skills deployed by managed settings are unaffected. It works from any settings file; in lab 3 it took effect from a file passed with --settings and from .claude/settings.json. In managed settings a true cannot be overridden, which is where a security team puts it.

A command checked into a repository runs its injections on the machine of whoever types it, with that person's credentials. Review !`…` lines and allowed-tools in a pull request the way you review a script.
Inject the smallest output that answers the question: --stat before a full diff, -n 20 before a whole log.

Pinning a cheap model

A command that formats, classifies or summarizes does not need the session's best model. With model: haiku in the frontmatter and the session started with --model sonnet, the run's modelUsage held one key, claude-haiku-5-5, and cost about $0.0015. The same body without the field ran on claude-sonnet-5-5 and cost about $0.028, roughly eighteen times as much for the same one-line answer. On a subscription the saving is window share rather than dollars; the ratio is what to look at in both cases.

In auto mode, or when an organization's availableModels allowlist excludes the value, the session keeps its own model and the field is quietly ignored. Confirm from modelUsage, not from the frontmatter.

allowed-tools is a grant, and it travels

Workspace trust does not gate the field: a project command's allowed-tools applies even in a -p run in a folder you have never trusted. A repository can therefore grant its own commands broad tool access. Deny and ask rules in your settings still win over it, and an organization can switch the field off for repository commands with allowManagedPermissionRulesOnly.

context: fork is not a fork of your conversation

Despite the name, the subagent starts empty apart from its own system prompt, CLAUDE.md (except for Explore and Plan, which skip it) and the rendered command body. Put everything the task needs in the body. A body that holds only guidelines, with no task, comes back with nothing useful. In the terminal a forked command runs in the background unless you set background: false; in claude -p the run waits for it.

Fork a command when its work would flood your context with reading (a repository survey, a long log); keep it inline when you need its output in the conversation to act on.

Commands run headless

Pass a command as the prompt: claude -p "/unowned tickets.csv". Claude Code renders it exactly as at the terminal: arguments, injections, model and tool grants. Combined with --output-format json, a command becomes a function you can call from a scheduled task or a pipeline step and check by its result, subtype and total_cost_usd. Three flags keep such a run reproducible:

FlagWhy
--setting-sources projectLoads only the repository's settings, not the caller's personal ones.
--strict-mcp-configIgnores every MCP server not passed with --mcp-config.
--max-turns NBounds the run. Allow two or three turns even for a one-shot command (lesson 2).

To run with no commands at all, --disable-slash-commands turns off every skill and command for the session.

A command is a prompt under change control

A prompt typed into a chat is lost and differs every time. The same prompt in .claude/commands/ is a file: it has a diff, a reviewer, a history and a name everyone types the same way. Treat it as code.

  • One job per command, named by verb: /unowned, /release-notes, /triage.
  • A fixed output shape stated in the body (Reply with exactly one line in the form MISSING=<count>), so a script can check it.
  • A done-test kept next to it: a small fixture and the expected result. Lab 5's test ran the command three times against a five-row CSV and passed 3 of 3 with MISSING=2.
  • disable-model-invocation: true on anything with side effects.
  • The narrowest allowed-tools that lets it finish without a prompt.

Command, hook or script

A command is a request to a model: it can misread, improvise or stop early. Choose by what the task needs.

The taskUseBecause
Needs judgment: summarize, classify, draft, review.CommandOnly the model can do it; the command makes it repeatable.
Must happen every time an event occurs: block a write, format after an edit, log every tool call.HookA hook runs on the event whether or not anyone types anything, and the model cannot talk its way past it.
Is fully deterministic: count rows, rename files, call an API.ScriptFaster, free and exact. Call it from a command's injection or allowed-tools if the model needs the result.
Is a rule that should always be in force.CLAUDE.md or a settingA command applies only when someone remembers to type it.

Lab 5's /unowned is honest about this: counting empty cells in a CSV is a one-line script. It is a good lab because the answer is checkable, not because it is a good use of a model. The command earns its keep when the input is messy enough that a script would need judgment.

If you could write the done-test as the implementation, write the script instead.
A command used as a gate ("run /check before every commit") is only as reliable as the person who remembers to run it. Gates belong in hooks or CI.

Read the init line of a headless run, count the commands it lists, and call two built-ins headless at zero cost.

  1. Make the lab folder and move into it.

    New-Item -ItemType Directory -Force {{LAB}}/m4/lab1 | Out-Null; cd {{LAB}}/m4/lab1

  2. Run a one-line prompt with stream-json output. Every headless run in this module carries --setting-sources project and --strict-mcp-config: the first keeps your personal settings and hooks out, the second keeps your MCP servers out, so what you measure is Claude Code and the lab folder only.

    claude -p "Reply with the word OK." --model haiku --setting-sources project --strict-mcp-config --max-turns 1 --output-format stream-json --verbose > init.jsonl

    Expected: a file of about ten JSON lines. The first is the session's init message.

  3. Print the type, the model and the command list.

    $init = Get-Content init.jsonl -TotalCount 1 | ConvertFrom-Json
"type=$($init.type) subtype=$($init.subtype) model=$($init.model)"
"slash_commands: $($init.slash_commands.Count)"
$init.slash_commands -join ' '

    Expected: type=system subtype=init model=claude-haiku-5-5, then about 50 names (53 on 2.1.322) including context compact clear usage model effort mcp agents doctor. permissions, hooks, memory and plugin are absent: they are interactive-only.

  4. Call /context headless and read its cost.

    claude -p "/context" --model haiku --setting-sources project --strict-mcp-config --max-turns 1 --output-format json > context.json
$c = Get-Content context.json -Raw | ConvertFrom-Json
"num_turns=$($c.num_turns) cost=$($c.total_cost_usd)"; $c.result

    Expected: num_turns=0 cost=0, then a Context Usage report: about 17k of 1m tokens, with rows for System prompt (about 3.4k), System tools (about 11.6k), System tools (deferred), Skills (about 2.2k), Messages, Free space and Autocompact buffer, and a per-skill table.

  5. Do the same with /usage.

    claude -p "/usage" --model haiku --setting-sources project --strict-mcp-config --max-turns 1 --output-format json > usage.json
$u = Get-Content usage.json -Raw | ConvertFrom-Json
"num_turns=$($u.num_turns) cost=$($u.total_cost_usd)"; $u.result

    Expected: num_turns=0 cost=0. On a subscription the result starts "You are currently using your subscription" and shows the current session and current week as percentages with reset times. On an API key it shows session cost and tokens.

Self-check
  • How many names does your slash_commands array hold, and is permissions among them? Answer: about 50, and no; it only exists in interactive sessions.
  • Which /context category is largest before you type anything? Answer: System tools, the built-in tool definitions, at about 11.6k tokens. That is the fixed overhead every turn carries.
  • Why can a monitoring script call /context every minute without cost? Answer: it is a built-in that reads client state; num_turns 0 shows no model call was made.

Create a command that echoes its arguments, a namespaced command and a deliberate name clash, and read how each resolves.

  1. Make the folders.

    New-Item -ItemType Directory -Force {{LAB}}/m4/lab2/.claude/commands/ops, {{LAB}}/m4/lab2/.claude/skills/clash | Out-Null; cd {{LAB}}/m4/lab2

  2. Write the argument echo command.

    @'
---

argument-hint: <host> <symptom>
disable-model-invocation: true
---
Reply with exactly this one line and nothing else:
FIRST=$0 | SECOND=$1 | THIRD=$2 | ALL=$ARGUMENTS
'@ | Set-Content -Encoding utf8 .claude/commands/echo-args.md

  3. Call it with two arguments, the second one quoted with single quotes.

    claude -p "/echo-args web-01 'disk full'" --model haiku --setting-sources project --strict-mcp-config --max-turns 3 --output-format json > echo.json
(Get-Content echo.json -Raw | ConvertFrom-Json).result

    Expected: FIRST=web-01 | SECOND=disk full | THIRD=$2 | ALL=web-01 'disk full'. $0 is the first argument, and $2 stays literal because there is no third. The run costs about $0.001 to $0.002.

  4. Write a namespaced command and a clash: a command file and a skill with the same name.

    @'
---
description: Restart note for a host
---
Reply with exactly: RESTART-NOTE for $ARGUMENTS
'@ | Set-Content -Encoding utf8 .claude/commands/ops/restart.md
'Reply with exactly: FROM-COMMAND-FILE' | Set-Content -Encoding utf8 .claude/commands/clash.md
@'
---
description: Clash test skill
---
Reply with exactly: FROM-SKILL
'@ | Set-Content -Encoding utf8 .claude/skills/clash/SKILL.md

  5. Run the namespaced command and look at the custom names in its init line.

    claude -p "/ops:restart web-01" --model haiku --setting-sources project --strict-mcp-config --max-turns 3 --output-format stream-json --verbose > restart.jsonl
$init = Get-Content restart.jsonl -TotalCount 1 | ConvertFrom-Json
$init.slash_commands | Where-Object { $_ -match 'echo|ops|clash' }
(Get-Content restart.jsonl | Select-Object -Last 1 | ConvertFrom-Json).result

    Expected: the names clash, echo-args and ops:restart, then RESTART-NOTE for web-01.

  6. Run the clash.

    claude -p "/clash" --model haiku --setting-sources project --strict-mcp-config --max-turns 3 --output-format json > clash.json
(Get-Content clash.json -Raw | ConvertFrom-Json).result

    Expected: FROM-SKILL. The skill wins over the command file.

Self-check
  • What would the result have been with "/echo-args web-01 `"disk full`"" in Windows PowerShell 5.1? Answer: SECOND=disk; the embedded double quotes split the prompt and full is lost.
  • Which file do you delete to make /clash answer FROM-COMMAND-FILE? Answer: .claude/skills/clash/SKILL.md.
  • Why --max-turns 3 and not 1? Answer: a model-invocable command can make the model call the Skill tool on itself first, which uses up a one-turn budget and ends in error_max_turns with an empty result.

Build a command that reads a random marker from the newest commit body through !`…`, then switch injection off and watch the marker disappear.

  1. Make a repository with two commits. The second commit body holds a random ticket id.

    New-Item -ItemType Directory -Force {{LAB}}/m4/lab3/.claude/commands | Out-Null; cd {{LAB}}/m4/lab3
git init -q
$nonce = 'ticket-' + (Get-Random -Minimum 10000 -Maximum 99999)
'one' | Set-Content a.txt; git add a.txt; git -c user.name=lab -c user.email=lab@example.com commit -q -m "Add a.txt"
'two' | Set-Content b.txt; git add b.txt; git -c user.name=lab -c user.email=lab@example.com commit -q -m "Fix b.txt" -m "Refs $nonce"

Take a prompt you type more than once a week, make it a project command with a fixed output shape, and keep a script that proves it works.

  1. Work through the worked example first. It counts tickets with no owner in a CSV.

    New-Item -ItemType Directory -Force {{LAB}}/m4/lab5/.claude/commands | Out-Null; cd {{LAB}}/m4/lab5
@'
id,host,summary,owner
101,web-01,disk 91 percent full,ana
102,web-02,cert expires in 6 days,
103,db-01,replication lag 40s,raj
104,web-01,nginx 502 spike,
105,dns-01,zone serial not bumped,lee
'@ | Set-Content -Encoding utf8 tickets.csv
@'
---
description: Count tickets with no owner in a CSV file
argument-hint: <csv-file>
disable-model-invocation: true
allowed-tools: Read
---
Read the CSV file $0. Count the data rows whose owner column is empty.
Reply with exactly one line in the form MISSING=<count> and nothing else.
'@ | Set-Content -Encoding utf8 .claude/commands/unowned.md

  2. Write the done-test as a script and run it. It calls the command three times and passes only if every answer is exact.

    @'
$pass = 0
foreach ($i in 1..3) {
  claude -p "/unowned tickets.csv" --model haiku --setting-sources project --strict-mcp-config --max-turns 3 --output-format json > "run$i.json"
  $r = Get-Content "run$i.json" -Raw | ConvertFrom-Json
  if ($r.result.Trim() -eq 'MISSING=2') { $pass++ }
  "run $i result=[$($r.result.Trim())] turns=$($r.num_turns) cost=$([math]::Round($r.total_cost_usd,4))"
}
"done-test: $pass of 3 passed"
if ($pass -eq 3) { exit 0 } else { exit 1 }
'@ | Set-Content -Encoding utf8 done-test.ps1
powershell -NoProfile -File .\done-test.ps1; "EXIT $LASTEXITCODE"

    Expected: three lines with result=[MISSING=2] turns=2, each at about $0.0005 when the prefix is already cached (a first run on a cold cache was about $0.002), then done-test: 3 of 3 passed and EXIT 0.

  3. Now your own. Pick a prompt from your shell history or chat log that you have typed at least three times. Write it to .claude/commands/<verb>.md in a real repository. Use named arguments for its parameters, state an exact output shape in the body, set disable-model-invocation: true if it changes anything, and grant only the tools it needs in allowed-tools.

  4. Copy done-test.ps1 next to it, change the call, the fixture and the expected answer, and run it until it passes 3 of 3. Then decide, using the table in the last lesson, whether the task should have been a script or a hook instead.

    Expected: your done-test prints 3 of 3 passed and exits 0.

Self-check

Done-test: a command file in a repository and a script beside it that exits 0 after three passing headless runs. Then answer:

  • Does your done-test compare an exact string or a pattern? Answer: prefer exact. If the answer is free text, make the body end with a fixed line (VERDICT=pass) and test that line.
  • What does a run that passes 2 of 3 tell you? Answer: the prompt is ambiguous or the model too weak for it. Tighten the output shape before you reach for a bigger model.
  • Could the done-test itself do the job? Answer: if yes, as with counting empty CSV cells, replace the command with the script.
