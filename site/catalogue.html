Thirteen modules

Run it, read the meter, then change one thing.

A bootcamp on using Claude Code and LLMs well, for people who already run systems for a living. It is a set of separate modules. Take one, take a path, or take them all: each module is its own page with a briefing in several lessons, hands-on labs you run in a scratch folder, judgment calls, and a cheat sheet. Every lab ends in a number or a file you can check, because the habits that matter here are measuring and verifying.

Pick by levelFoundation modules assume nothing but a working install. Practitioner modules build things. Advanced modules run them at scale and prove what changed.

Before the first lab
  • Claude Code 2.1 or later, signed in with a plan or an API key. Check with claude --version.
  • One scratch folder for all labs. The labs call it {{LAB}}, with a subfolder per module. Nothing is written outside it unless a step says so, and every lab that installs something ends with its removal.
  • Commands are written for PowerShell. Every claude command is the same in any shell; only the file-creation lines differ.
  • Headless labs pass --setting-sources project --strict-mcp-config so your personal settings, hooks and MCP servers stay out of the measurement. Small runs use the cheapest model tier.
  • Numbers in the Expected lines were measured on real runs in November 2026. Yours will differ a little; the shape should not.
Export and share

Every module travels alone

Each module is its own page with its own link, and also its own self-contained HTML file. Send one module to one person, or the whole set to a team. This edition names no organization, host, account or internal tool.

  • A link. On claude.ai, open the module and use Share. A viewer needs only the link.
  • A file. Each module page has "Save this module as a file" under Export and share. The file needs no server and no network.
  • The folder. This catalogue (index.html) and the module files in one folder link to each other offline, and work unchanged behind any static web server.

Progress is kept per module in the browser that opened it. Each module's overview has a progress code to carry it to another device or copy.
